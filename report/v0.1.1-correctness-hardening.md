## 新的独立发现：记录，不扩 scope

1. **QA `output-is-new-file` 仍只比较 plan 路径字符串。** 对 intake 产生的真实 plan，在 planned output 建立 source 的 hardlink，`wf-qa.sh --no-compat` 返回 `ok: true`，`output-is-new-file: pass`。实际 inode 相同。写入脚本已拒绝这种 alias，但 QA 对外部伪交付的证明仍不充分。
   - 证据：`tests/.out/hardening/independent-findings/qa-alias-result.json`、`qa-alias-identity.txt`、`qa-alias-plan.json`。
2. **compat cleanup 的 process ownership 判断不足。** `kill_new_wait` 把 baseline 之后出现的全部 Word/WPS/PowerShell PID 当作本轮创建，LibreOffice-only harness 也执行这个 cleanup。并发验证中观察到 WPS failed、Word missing cache / PowerShell exit 1；串行重跑通过。把失败归因到具体 cleanup kill 是基于代码和时间重叠的推断，尚未采集逐 PID 的 kill trace。产品代码不在本轮额外修复；验证编排对 LibreOffice-only tests 禁用 Windows driver，并将原生 COM suites 放在其他 suites 完成后串行运行。
   - 证据：`03-standard-styles/crossref-cache.log`、`crossref-cache-recheck.log` 及相应 harness `result.json`。

3. **冻结的 nested-table fixture 自身不满足严格宽度等式。** OfficeCLI read-back：外层 `width=6803`，`colWidths=3402,3402`，sum=6804。schema/render 通过不能证明严格宽度不变量成立。没有修改 fixture；新测试只在临时副本上校正宽度以验证支持条件。
   - 证据：`tests/.out/hardening/independent-findings/nested-fixture-table.json`。

4. **TOC cache 测试存在共享 staging 目录竞态。** `tests/toc-cache.sh` 固定使用 `/mnt/c/temp/wordflow-toc-test`，在 per-probe lock 外创建 / 写入 / 删除。多个独立快照同时测试时可互相删除 `probe.ps1` / `fixture.docx`。`05` / `06` 的 WPS F9 probe 均出现 empty output；无其他原生 probe 的串行重跑均 40/40。共享目录竞态由代码确认；本次具体 empty output 的触发原因没有逐文件事件 trace，因果归因仍是推断。
   - 原始证据：`05-qa-constructs/toc-cache.log`、`06-preview-artifacts/toc-cache.log`；重跑：对应 `toc-cache-serial-recheck.log`。测试脚本不额外修复；持久回归 runner 对整个 COM suite 使用独立 outer lock，避免后续验证互相干扰。
