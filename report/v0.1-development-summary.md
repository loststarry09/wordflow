- **Date:** 2026-10-02
- **Outcome:** v0.1.0 shipped and tagged. Both workflows — generate-from-content and
  tidy-existing — are implemented, acceptance-tested, and merged to `main`; the full-feature

- **How to read this:** the durable rules are in [`docs/spec/v0.1.md`](../docs/spec/v0.1.md),
  the ADRs, and `references/`; the current state is
  [`PROJECT_STATUS.md`](../PROJECT_STATUS.md); the acceptance evidence is
  [`2026-10-02-v0.1-acceptance.md`](./2026-10-02-v0.1-acceptance.md). This file is the

## 1. What shipped

WordFlow is a Word layout **skill for agents**: a judgement layer that decides *which*
OOXML/OfficeCLI construction to use and *why*, delegating every DOCX read and write to
OfficeCLI (ADR-0001). v0.1 does two jobs of equal priority (spec §D4, §D5):

- **generate** a laid-out `.docx` from content (optionally a template and/or a written
  formatting requirement);
- **tidy / restyle** an existing `.docx` without touching its words, images, tables, or
  equations.

Both produce a **new** file (ADR-0003), a five-area **change report** (spec §D12), and — by
default — a **render preview** (spec §D13). Simplified Chinese is a first-class default
(spec §D6). The capability tiers (fully supported / limited / out of scope) and the
compatibility promise ("opens without repair", not pixel-identical — ADR-0004) are in the
spec §D9/§D10.

## 3. Architecture and the contracts that held

- **Layering never needed rework.** WordFlow judgement + `scripts/wf-*.sh` orchestration; every
  DOCX read/write through OfficeCLI. No parser, renderer, or writer was introduced (ADR-0001).
- **Four cross-cutting contracts composed cleanly** and were frozen before parallel work began:
  the **job plan** (`wf-intake.sh`, precedence + output path + source hash), the **change
  report** (`wf-change-report.sh`, five areas), the **risk policy** (`wf-risk-policy.sh`, one
  trigger table, no per-feature warn/downgrade logic), and the **pipeline**
  (`wf-pipeline.sh`, which composes the capabilities and reimplements none).
- **Capabilities are self-contained scripts** (`wf-headers`, `wf-image`, `wf-table`,
  `wf-caption`, `wf-crossref`, `wf-toc`, `wf-footnote`, `wf-equation`, `wf-template`), each
  protecting the source, performing DOCX work through OfficeCLI under `timeout`, verifying its
  own effect by reading the output back, routing warnings/downgrades through the risk policy,
  and shipping with a fixture-driven suite.
- **A byte copy is not a DOCX write.** The new output file is produced by copying the source's
  bytes and then mutating that copy only through OfficeCLI; ADR-0003 records this reading.

## 4. Durable technical findings

The measured facts live in `references/research/` and the implementation rules in
`references/`; the headlines v0.1 turns on:

- **Nothing recalculates fields on open.** Word, WPS, and LibreOffice display the **cached**
  result verbatim and none honours `updateFields` on open. A pre-computed cache is mandatory,
  and it must be correct — a wrong page number is worse than none. `officecli add field`
  always writes a cache, but TOC/REF caches are **placeholders** and `evaluated`/`view issues`
  do not detect them; judge a field by its **cached text**
  (`references/research/field-recalc-and-cross-app-verification.md`).
- **The page-dependent carve-out.** `PAGE`/`NUMPAGES` (and an unlocked `PAGEREF`) are recomputed
  by each reader's layout engine per page, so a stale cache does not change what is shown — the
  basis for shipping real footer page numbers
  (`references/research/multipage-page-fields.md`).
- **TOC without page numbers.** The TOC is a real `TOC` field whose cache carries the heading
  entries and no page-number references; `pageNumbers=false` maps to the `\z` switch, so a
  manual F9 adds correct numbers later (`references/fields/table-of-contents.md`).
- **Correct cached cross-reference text.** The resolved target text is written into the `REF`
  result run and the `w:dirty` marker cleared with `raw-set`
  (`references/fields/cross-references.md`).
- **Portable constructs.** Inline images (floating images downgrade to centred inline);
  fixed-layout tables with explicit `colWidths` and direct borders; nested tables under
  `tblW == Σ colWidths`; first-page/odd-even headers; simple OMML equations (complex ones keep
  OMML and warn) — see `references/objects/` and the per-feature research notes.
- **Style identity.** `styleId` is the machine identity, `w:name` the UI label; match referenced
  to defined styles by **either** (`references/research/officecli-behavior.md`).
- **CJK fonts must be explicit.** SimSun body / SimHei headings with explicit Latin pairing;
  never inherit OfficeCLI's locale default `等线`/DengXian, which has no CJK coverage on Linux
  (`references/research/cjk-font-availability.md`).
- **Version matrix pinned** by #10 (`references/research/version-matrix.md`); Word/WPS are
  drivable from WSL over COM and LibreOffice headless, so all three are measurable in the
  compatibility harness (`references/compatibility/harness.md`).

## 5. Defects found and fixed

| Defect | Symptom | Fix |
|---|---|---|
| #36 style identity | `wf-style-ownership.sh` matched by display name only, reporting a false dangling `Normal` on standard-style output. | Match by `styleId` **or** name (mirrors the D14 check). |
| #38 harness relative path | `wf-compat-harness.sh` hung LibreOffice when `--out` was relative. | Absolutise `--out`; regression added. |
| #39 fixture width | `tables/fixed-table.docx` had `ΣcolWidths ≠ tblW`, invalidating the nested-table probe. | Regenerated with `colWidths=1701,1701,1700`. |
| #37 spec/status drift | Spec/status listed nested tables, first-page/odd-even headers, and complex equations as limited/untested. | Updated from the #3–#7 measurements (promotions + construct-specific risk). |

Two early "facts" were corrected by measurement rather than trusted: `refresh` does **not**
require Word/Windows (it has an HTML backend on Linux), and `refresh` does **not** resolve
`REF` (its cache stays the `«target»` placeholder).

## 6. Design influences

The initial research pass borrowed deliberately from existing practice; these shaped the
architecture and the ADRs:

- **Reference-document style contract** (Pandoc `--reference-doc`, Quarto) — layout lives in a
  template; content only references style names. → template adoption (#27).
- **Style existence is a precondition, verified** (python-docx: an undefined style is a silent
  no-op) — define styles, read back. → the standard style set and the dangling-style QA check.
- **Three separate checks** (construction ≠ schema validation ≠ visual render; Open XML SDK,
  OfficeCLI `validate` / `view issues` / screenshot) → the D14 checklist and the acceptance
  workflow.
- **Layered precision** (OfficeCLI L1 semantic props → L2 attribute fallback → L3 `raw-set`,
  raw XML only with a recorded reason) → the SKILL core rules.
- **Executable delivery gates, not prose checklists** (OfficeCLI delivery gates) → `wf-qa.sh`.
- **Render-and-look** (Anthropic docx skill `soffice` → `pdftoppm` → inspect) → the render
  preview and the LibreOffice render measurements.
- **Known-issue taxonomy** (agent-error vs renderer-bug vs skill-gap) and **normalise runs
  before text edits** → judgment habits in the references.
- **Fields are live values with caches** (Pandoc issue #458) → pre-cache every field, ship real
  fields.

## 7. Delivery method

The implementation batches used an **orchestrator + parallel sub-agents** pattern: one GitHub
issue per agent, an isolated `git worktree`/branch per issue, dependency-gated dispatch,
interface contracts frozen up front, review before merge, `--no-ff` merges to preserve feature
commits, and a full regression after every merge. The `#2` compatibility harness and every
Word/WPS COM call were serialized with `flock`; LibreOffice used isolated profiles. The main
agent was the sole orchestrator and never delegated the merge or regression step.

## 8. Final verification (v0.1.0)

All on OfficeCLI `1.0.153`, Word `16.0`, WPS Writer `12.0`, LibreOffice `24.2.7.2`:

- **`tests/acceptance.sh`** — 51 checks, both workflows, tiers, DoD, source protection.
- **Compatibility gate** — 12/12 acceptance output × application records open repair-free
  (Word/WPS/LibreOffice); `tests/compat-harness.sh` 42/42.
- **`tests/validate-fixtures.sh`** — 65 checks over 32 fixtures.
- **`tests/pipeline.sh`** 63 · **`tests/generate.sh`** 73 · **`tests/tidy.sh`** 54 ·
  **`tests/qa.sh`** 33 · **`tests/skill-discovery.sh`** 20, plus every unit and feature suite.
- **1,495 checks across 27 suites, all passing**; `shellcheck -S warning` clean.

Known limitations are recorded in
[`2026-10-02-v0.1-acceptance.md`](./2026-10-02-v0.1-acceptance.md): formatting-requirement
overrides without a template are reported unverified; automated restructuring is out of v0.1
(a confirmed request is a reported downgrade); floating images downgrade to inline; pagination
is not pixel-identical across applications.
