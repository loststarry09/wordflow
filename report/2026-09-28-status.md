# WordFlow — 当前状态总结

- **日期**：2026-09-28
- **一句话**：需求已澄清、兼容性研究已完成实测；**下一步是写 v0.1 规格（spec）**。目前尚未写任何排版规则，也没有实现代码。
- **本文件**：面向人的整体状况综述；细节以链接的其他文档为准，不重复。

## 1. 项目是什么（已定案）

- **WordFlow = 判断/知识层**，决定文档"应该长什么样"；**OfficeCLI = 唯一执行层**，所有 DOCX 读写都交给它（ADR-0001）。WordFlow 不是引擎、解析器或渲染器。
- 只处理 `.docx`；不做 PDF/Markdown 等格式转换；不依赖 Microsoft Word 或 Windows。
- 受众：不是排版专家的普通用户，想要一份排版正确、可在多款软件打开、且后续可维护的文档。

## 2. v0.1 需求与边界（已定案）

- **两类任务同等重要**：由内容生成新文档；整理已有的 `.docx`。
- **只改呈现**；改结构必须用户明确要求并逐项确认；**永不改文字**（ADR-0002）。
- **输入**：内容（文本/Markdown，可含图片、表格数据）＋可选**模板**和/或**文字格式要求**；优先级 **文字要求 > 模板 > WordFlow 默认**。
- **输出**：**新文件**，默认名 `原文件名-排版.docx`（重名加序号，可指定路径），**源文件永不修改**（ADR-0003），v0.1 无原地编辑。每次附 **Change report**（改了什么／替你做的格式决定／警告与未验证项）；预览默认提供、可关。
- **无规范时**：直接产出并透明列出决定；只问最少必要信息；**简体中文为一等公民**。
- **整理已有文档**：默认沿用其原有样式并规范化；无可复用样式才用标准样式；模板优先于文档原样式。
- **风险行为**：降级永不静默；可能渲染不同的构造 → 警告后继续；要改文字/未确认的改结构/源文件不可安全读取 → 停止并询问。
- **完成门槛**：文档能打开且不弹修复 ＋ WordFlow 自查清单全绿；结构改动还需用户逐项确认。
- **兼容性**：Microsoft Word / WPS Writer / LibreOffice Writer 均能打开且不弹修复是硬门槛（ADR-0004）；**不承诺像素级一致**。
- **形态**：安装给编码助手（opencode / Claude / Codex）的 skill，`SKILL.md` 为入口；不做独立 CLI。
- 能力分档（完整／受限／不做）见 `report/2026-09-28-requirements-grilling.md`。

## 3. 兼容性研究结论（已在本机实测）

验证方法：OfficeCLI 1.0.152；Word 16.0 与 WPS 12.0 经 COM 从 WSL 驱动；LibreOffice 24.2.7.2 在 WSL 内 headless 驱动。完整记录见 `references/research/field-recalc-and-cross-app-verification.md`。

**域 / 目录 / 交叉引用**

| 行为 | Word 16 | WPS 12 | LibreOffice 24.2 |
|---|---|---|---|
| 打开文档时重算域 | 否 | 否 | 否 |
| 理会 `updateFields` | 否 | 否 | 否 |
| 显示占位/陈旧缓存 | 原样显示 | 原样显示 | 原样显示 |
| 自动重建目录 | 否 | 否 | 否 |
| 自动解析 `REF` | 否（需 F9） | 否（需 F9） | **是** |
| 目录页码来源 | 文档缓存 | 文档缓存 | 文档缓存 |

- **三款都不会自己更新域**：文档里写什么缓存，就显示什么。因此**必须预填缓存**，而且**必须填对**。
- OfficeCLI `add` 时总会写入缓存，但 TOC/REF 是**占位符**（`Update field to see table of contents`、`«target»`），`evaluated=true` 与 `view issues` 都发现不了 —— 必须看缓存文本。
- OfficeCLI `refresh` 写入的目录页码来自它自己的 HTML 分页模型，**对三款软件都是错的**（写 2，它们实际算 1）。

**渲染保真（LibreOffice 实测）**

- 简单公式、**合并单元格表格**、页码重排（含小写罗马数字）、居中 PAGE 页码：**忠实渲染**。
- **浮动（锚定）图片：不忠实**（变左对齐随文，未居中/浮动）。
- 中文：`SimSun` 真实嵌入；`Microsoft YaHei` 被替换为 `WenQuanYi Zen Hei`；`fc-match 等线 → DejaVu Sans`（无中日韩字形）。**OfficeCLI 的 `zh-CN` 默认字体「等线」在 Linux/LibreOffice 上不安全**。

## 4. 研究对需求的直接影响

1. **目录页码无法保证正确** —— 没有真正的排版引擎。spec 需三选一：目录不带页码 / 尽力填并提示"请按 F9 更新" / 要求用某款 Office 收尾（与"不依赖 Word"冲突）。
2. **能力分档需微调**：合并单元格表格可从"受限"升为"完整支持"；浮动图片确认归"受限支持"。
3. **默认中文字体必须另选**（不能依赖「等线」）。
