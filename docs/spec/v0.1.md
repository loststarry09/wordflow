# WordFlow v0.1 — Product Spec

- **Status:** ready-for-agent
- **Date:** 2026-09-29
- **Tracker:** [GitHub issue #1](https://github.com/loststarry09/wordflow/issues/1) (published copy)
- **Requirements source of truth:** [`PROJECT_STATUS.md`](../../PROJECT_STATUS.md), [`CONTEXT.md`](../../CONTEXT.md), ADR-0001 … ADR-0004
- **Scope of this document:** the behaviour WordFlow v0.1 promises. No implementation, no OfficeCLI command syntax, no OOXML schema.

This spec describes how **WordFlow** should behave. It is written in the project's ubiquitous language
(`CONTEXT.md`): WordFlow, OfficeCLI, layout, content, restyle, restructure, standard styles, source/output
document, change report, warn/downgrade/refuse, portable, standards-based, reproducible. It does not restate
or override ADR-0001 … ADR-0004; where it touches them it defers to them.

---

## Problem Statement

A non-expert with a `.docx` on their hands — or with content they need to turn into one — has no reliable way
to get a *correct, portable, maintainable* document. Three failures recur:

1. **The layout is guessed.** Fonts, sizes, spacing, indentation, margins, and headings are applied by hand or
   not at all. The result looks improvised and is hard to keep consistent.
2. **It breaks somewhere else.** A document that looks right in one application opens with a repair prompt,
   renders differently, or shows stale/placeholder generated content in another. The user does not find out
   until a colleague, a reviewer, or a submission portal sees it.
3. **The tools don't know what "correct" is.** An agent can *operate* a `.docx` through OfficeCLI, but nothing
   tells it **which** construction to choose and **why**, or which choice survives Microsoft Word, WPS Writer,
   and LibreOffice Writer — and the user is not a Word expert who can adjudicate.

The user wants the document laid out properly, once, without becoming a Word expert and without the source
being put at risk.

## Solution

WordFlow is a **skill installed into a coding agent**. It is the judgement/knowledge layer that decides **how a
document should be shaped** and delegates **every** read and write to OfficeCLI (ADR-0001). It does two jobs of
equal priority:

- **Generate** a laid-out `.docx` from content the user supplies.
- **Tidy** (restyle) an existing `.docx`, leaving every word, image, table, and equation untouched.

In both cases WordFlow:

- owns **layout only** and never writes or edits **content** (ADR-0002);
- writes a **new** output document and never modifies the source (ADR-0003);
- produces a result that opens **without a repair prompt** in Word, WPS Writer, and LibreOffice Writer and
  renders faithfully from one shared portable subset — not pixel-identical (ADR-0004);
- lists, in a **change report** shipped with every output, what it changed, every formatting decision it made
  on the user's behalf, every downgrade, and anything it could not verify;
- defaults to **Simplified Chinese** typography without being told to;
- asks only the minimal question whose absence would cause rework, and otherwise produces directly.

## User Stories

1. As a non-expert, I want to hand over my content and receive a properly laid-out `.docx`, so that I do not
   have to know Word's formatting model.
2. As a non-expert, I want to hand over an existing `.docx` and have its layout tidied, so that I do not have to
   restyle it by hand.
3. As a document owner, I want my source file left completely untouched, so that a bad result can never destroy
   my original.
4. As a document owner, I want the output to be a new file, so that I can compare it against the source and
   re-run a job if I dislike it.
5. As a document owner, I want the output named `<source name>-排版.docx` by default, so that I can recognise it
   without a manual rename.
6. As a document owner, I want an existing output name to be numbered rather than overwritten, so that I never
   lose an earlier result.
7. As a document owner, I want to specify the output path, so that the file lands where I expect.
8. As a writer in Chinese, I want a good Chinese layout by default without stating it, so that the common case
   needs no configuration.
9. As a writer in Chinese, I want a 2-character first-line indent and suitable body/heading fonts, so that the
   result matches normal Chinese document conventions.
10. As a writer mixing Chinese and Latin text, I want both scripts to use appropriate fonts, so that neither is
    silently substituted into an unreadable or mismatched face.
11. As a user, I want to supply a written formatting requirement (fonts, sizes, spacing, indentation, margins),
    so that the result follows my instruction rather than WordFlow's taste.
12. As a user, I want a supplied formatting requirement to override a template and WordFlow's defaults, so that
    my explicit instruction always wins.
13. As a user, I want to supply a template whose look is adopted, so that the output matches my organisation's
    or school's style.
14. As a user, I want the template's content kept out of my document, so that I do not accidentally inherit
    someone else's words.
15. As a user, I want WordFlow to preserve and tidy the style set already present in my document, so that my
    document keeps its own identity.
16. As a user, I want WordFlow to fall back to a clean standard style set only when my document has no usable
    styles, so that I am not given an incoherent mix.
17. As a user, I want WordFlow to ask me only the one or two questions that would otherwise cause rework
    (language, document type), so that I am not interrogated.
18. As a user, I want WordFlow to proceed and tell me what it decided, so that I can trust the result without
    having approved every choice.
19. As a reader, I want a real heading hierarchy, so that the document is navigable and its structure is visible.
20. As a reader, I want the document to have a sensible page size, orientation, and margins, so that it prints
    and displays correctly.
21. As a reader, I want consistent body text — font, size, line spacing, indentation — so that the document looks
    deliberate.
22. As a reader, I want recognisable, consistent heading levels, so that I can find and follow sections.
23. As a reader, I want a header and/or footer and page numbers where appropriate, so that the document is
    usable in print.
24. As a reader, I want a table of contents that lists the document's headings, so that I can navigate it.
25. As a reader, I want the table of contents to show correct page numbers, so that I can jump to the right page —
    and I want to be told plainly if WordFlow cannot guarantee them.
26. As a reader, I want inline images placed correctly in the text flow, so that figures appear where they belong.
27. As a reader, I want regular tables formatted consistently, so that data reads cleanly.
28. As a reader, I want a table with merged cells to keep its merge, so that grouped headers and spans survive.
29. As a reader, I want figure and table captions, so that figures and tables are labelled and referenceable.
30. As a reader, I want cross-references to sections, figures, tables, and equations that resolve to the right
    target, so that "see Section 3" is actually true.
31. As a reader, I want footnotes on the page they belong to, so that annotations stay close to their text.
32. As a reader, I want simple inline and display equations to render as real equations, so that they look
    mathematical rather than like plain text.
33. As a user, I want no placeholder text ever shipped silently, so that I never hand over an unfinished document
    thinking it is finished.
34. As a user, I want every downgrade reported, so that I know when a preferred construction was replaced.
35. As a user, I want to be warned, not blocked, when a construct may render differently in one application, so
    that I can decide whether the risk matters.
36. As a user, I want WordFlow to stop and ask rather than guess, when it would have to change my content, when I
    have not confirmed a restructure, or when it cannot read my source safely, so that it never silently does
    something I did not ask for.
37. As a user, I want a change report with every output, so that I know exactly what happened without reading the
    file.
38. As a user, I want a visual preview of the output by default, so that I can check it before using it.
39. As a user, I want to switch the preview off, so that a quick batch job does not pay for it.
40. As a user, I want the same source and the same instructions to produce the same layout, so that I can re-run
    a job and trust it.
41. As a user, I want WordFlow to be honest about what it could not verify, so that "it works" is a claim I can
    trust.
42. As a user on Word, I want the document to open without a repair prompt, so that I am not embarrassed by a
    corrupt-file warning.
43. As a user on WPS Writer, I want the same document to open without a repair prompt, so that I am not locked
    into one office suite.
44. As a user on LibreOffice Writer, I want the same document to open without a repair prompt, so that I can use
    free software without losing fidelity.
45. As a user, I want the output built from broadly supported constructs, so that it stays usable as applications
    change.
46. As a user, I want WordFlow to restyle without restructuring, so that a tidy-up does not silently reorder my
    document.
47. As a user, I want restructuring — heading levels, section order, paragraph grouping — only when I explicitly
    ask and confirm it item by item, so that my organisation is respected.
48. As a user, I want WordFlow to refuse a source it cannot read safely, so that it does not produce a corrupted
    or misleading result.
49. As a user, I want to know which capabilities are fully supported, which are limited, and which are out of
    scope, so that I can predict the result.
50. As an agent, I want a clear rule for when to warn, when to downgrade, and when to stop, so that I behave
    consistently.
51. As an agent, I want to know my boundary against OfficeCLI and OfficeCLI's own skills, so that I do not
    duplicate or contradict them.
52. As a maintainer, I want fixtures and checks that verify each promised capability, so that regressions are
    caught before a user sees them.

## Implementation Decisions

This section records product-level decisions and the technical settled points behind them. It deliberately does
**not** name OfficeCLI commands or OOXML elements as requirements.

### D1 — Responsibility boundaries

| Role | Owns | Must not |
|---|---|---|
| **WordFlow** | The judgement: which styles, structures, and portable constructions to use, and why; all layout decisions; the change report; the QA checklist. | Read or write a `.docx` directly; contain a parser, renderer, or writer; author or edit content. |
| **OfficeCLI** | Every read and write of a `.docx`; schema authority for element/property names. | Decide which construction is appropriate; promise portability. |
| **OfficeCLI's own skills** | Command syntax, per-element reference, format-level "can/how" knowledge. | Replace WordFlow's layout judgement. |

WordFlow does not replace OfficeCLI's skills; it is the layout-judgement layer on top of them. `SKILL.md` is
WordFlow's entry point and is not expanded by this spec.

### D2 — Inputs, outputs, precedence

- **Inputs:** content (text/Markdown, optionally images and table data) **or** an existing `.docx`; optionally a
  **template** and/or a written **formatting requirement**.
- **Output:** a **new** `.docx`, default name `<source name>-排版.docx`, numbered on collision, path specifiable.
- **Precedence (highest first):** formatting requirement → template → the source document's own styles (for a
  restyle) → WordFlow standard styles → WordFlow defaults.
- Every output is accompanied by a **change report** (D12) and, by default, a **render preview** (D13).

### D3 — Source-document protection

- The source is opened **read-only** and is never modified, in either workflow (ADR-0003).
- The output is always a **new** file; v0.1 has no in-place editing.
- Default output naming is collision-safe: `<source name>-排版.docx`, then `-排版 (2)`, `-排版 (3)`, …
- WordFlow verifies the source is unchanged after a job (its content is identical) before reporting done.
- If the source cannot be read or fails schema validation, WordFlow **refuses** and asks (D11).

### D4 — Workflow: generate from content

1. **Intake** — receive content, optional template, optional formatting requirement. Ask the minimal question
   only when the answer would change the result (language, document type). Default language: Simplified Chinese.
2. **Inspect** — read any supplied template/document; never modify it.
3. **Plan** — choose the style set and section setup (template look, else standard styles), and the content
   mapping (which paragraphs are headings, body, captions, quotes, lists).
4. **Build** — create the output document through OfficeCLI, applying styles rather than ad-hoc formatting;
   content is placed, never rewritten.
5. **Populate automatic content** — table of contents, captions, cross-references, footnotes, equations, using
   portable constructions; no placeholder may ship (D9, D11).
6. **Verify** — run the QA checklist (D14) and, where needed, the compatibility checks (D10).
7. **Preview** — produce the render preview unless disabled (D13).
8. **Deliver** — write the new file and the change report.

### D5 — Workflow: tidy (restyle) an existing document

1. **Intake** — receive the source `.docx`, optional template, optional formatting requirement.
2. **Inspect** — read the source and inventory its styles and structures. The source is not modified.
3. **Decide style ownership** — if the source has a usable, coherent style set, **preserve and tidy** it; if it
   has none, **rebuild** with WordFlow standard styles; a supplied template outranks the document's own styles;
   a formatting requirement outranks both.
4. **Restyle** — change layout only. Every word, image, table, and equation is left untouched.
5. **Restructure only on request** — heading levels, section order, or paragraph grouping change only if the
   user explicitly asked, and each change is confirmed item by item; otherwise WordFlow does not restructure.
6. **Verify, preview, deliver** — as in D4 steps 6–8.

### D6 — Default layout behaviour (Simplified-Chinese-first)

WordFlow applies these defaults only when the formatting requirement, the template, and (for restyles) the
document's own styles do not specify otherwise.

| Setting | Default |
|---|---|
| Page | A4, portrait |
| Margins | top/bottom 2.54 cm, left/right 3.17 cm |
| Body text | 宋体 (SimSun) 12 pt (小四), Latin face Times New Roman, 1.5 line spacing, first-line indent 2 characters, justified |
| Body paragraphs that must not indent | use the no-indent body style (lists, captions, and similar) |
| Title | 黑体 (SimHei) 22 pt (二号), centred, no first-line indent |
| Headings 1–4 | 黑体 (SimHei), 16 / 14 / 13 / 12 pt (三号 / 四号 / …), no first-line indent, space before/after |
| Captions | 宋体 10.5 pt (五号), centred, no first-line indent |
| Footnotes | 宋体 9 pt (小五) |
| Header / footer | 宋体 9 pt (小五) |
| Latin in headings | Arial |

**Frozen decision — default Chinese font strategy.** WordFlow **sets its fonts explicitly** and never inherits
OfficeCLI's locale default (`等线`/DengXian), which has no CJK coverage on Linux and substitutes to a Latin
font. Body CJK is 宋体 (SimSun) and heading CJK is 黑体 (SimHei), each paired with an explicit Latin face, so
mixed CJK/Latin runs are handled by design. Font substitution on a system that lacks these fonts is the
operating system's behaviour, is outside WordFlow's control, and is reported as an unverified item when relevant.

### D7 — Style system

- **Styles are the source of formatting truth.** Layout is expressed through paragraph and character styles;
  direct run formatting is reserved for genuine, isolated exceptions.
- **Style ownership:** preserve and tidy an existing coherent set by default; use the standard set only when the
  document has none; a template or formatting requirement overrides.
- **Frozen decision — WordFlow standard style set.** The set is:

  | Style | Role |
  |---|---|
  | `Normal` / 正文 | Default body paragraph (indented) |
  | `BodyNoIndent` / 正文无缩进 | Body paragraphs that must not indent |
  | `Title` / 标题 | Document title |
  | `Heading 1` … `Heading 4` / 标题 1–4 | Heading hierarchy (outline levels 1–4) |
  | `Caption` / 图注表注 | Figure and table captions |
  | `Quote` / 引用 | Block quotations |
  | `ListParagraph` / 列表段落 | List items |
  | `TOC 1` … `TOC 3` | Table-of-contents entries |
  | `FootnoteText` / `FootnoteReference` | Footnote text and reference mark |
  | `Header` / `Footer` | Running headers and footers |
  | `Hyperlink` | Links and resolved cross-references |

  Every style referenced anywhere in the document must be defined before use; a dangling style reference is a
  QA failure (D14). Heading levels beyond 4 are out of scope for v0.1.

### D8 — Element behaviour

- **Page, margins, headings, body** — per the D6 defaults; all overridable by higher-precedence inputs.
- **Headers / footers and page numbers** — WordFlow may add running headers/footers and page numbers; when it
  does, the header/footer is part of the layout it owns. Page numbers are produced as fields. Whether a
  page-number field displays the correct number on every page of a multi-page document **without a manual field
  update is unverified** and is a required verification item (Further Notes). Differing first-page / odd-even
  headers and page-number restart are **limited** (D9).
- **Images** — inline images are placed in the text flow and are fully supported. Floating (text-wrapped,
  anchored) images are **limited**: LibreOffice renders them left-aligned and in flow rather than floating, so
  WordFlow downgrades to a portable placement (typically centred inline) and reports the downgrade.
- **Tables** — regular tables are fully supported. **Merged-cell tables are promoted to fully supported**
  (frozen decision): LibreOffice 24.2 rendered `colspan` and vertical merges with borders exactly as intended.
  Nested tables remain **limited** (untested).
- **Captions** — figure and table captions use the caption style and an automatic numbering field; the numbering
  field's cached result must be correct, never a placeholder.
- **Cross-references** — references to a heading, figure, table, or equation must resolve to the correct target
  **in the cached result**, because no application updates fields on open. A content reference is fully supported
  when the cached target text is correct. A page-number reference is **limited**: WordFlow will not present a
  page number it cannot guarantee (D9), and downgrades to a content reference where possible.
- **Table of contents** — see D9 (frozen TOC page-number strategy).
- **Footnotes** — fully supported; footnote text and reference styles are defined.
- **Equations** — simple inline and display equations are fully supported (OMML renders faithfully in
  LibreOffice 24.2). Complex equations are **limited** (untested) and may be downgraded.

### D9 — Capability tiers (full / limited / out of scope)

**Fully supported** — produced, with QA, and expected to open and render faithfully:

- heading hierarchy (levels 1–4) and the full style set (D7);
- page size, orientation, margins;
- headers/footers and page numbers;
- table of contents (structure — see the frozen TOC decision below);
- inline images;
- regular tables;
- **merged-cell tables** (promoted in v0.1);
- captions;
- content cross-references;
- footnotes;
- basic (simple inline/display) equations.

**Limited — produced with a warning, or downgraded (always reported):**

- floating (anchored / text-wrapped) images;
- nested tables;
- multi-column layout;
- different-first-page and odd/even headers and footers;
- page-number restart;
- page-number cross-references (`see page N`);
- complex equations.

**Frozen decision — TOC page-number strategy.** WordFlow builds the table of contents **without page numbers**
in v0.1: the cached result lists the heading entries but carries no page-number references, because no
application updates fields on open and WordFlow has no layout engine, so any page number it produced would be
presented as finished while being wrong. The TOC remains a real, updatable field: the user can update it in
Word/WPS (F9 / Update TOC) to add page numbers. The change report states that page numbers are omitted and how
to add them. Page-number fields generally follow the same principle: WordFlow never presents a page number it
cannot guarantee. *(Mechanism open: how to cache TOC entries without page-number references is an implementation
decision — see Further Notes.)*

**Out of scope for v0.1:** editing content (ADR-0002); topic-to-article authoring; charts, comments, tracked
changes, forms/content controls, watermarks, references & citation styles, mail merge, text boxes / WordArt /
OLE; non-DOCX conversion; in-place editing (ADR-0003); a standalone CLI; document-archetype presets; any
Microsoft Word or Windows dependency.

### D10 — Compatibility promise

- **Hard gate:** the output opens in Microsoft Word, WPS Writer, and LibreOffice Writer **without a repair
  prompt**; this is the meaning of "portable" (ADR-0004).
- **Render fidelity:** faithful rendering from a shared portable subset — **not** pixel-identical. WordFlow
  prefers the one construction all three handle over per-application variants.
- **Target versions:** Word 2016+, current WPS Writer, LibreOffice 7.6+. WPS conclusions are labelled
  best-effort/unverified (closed source, no format documentation).
- **Verified fidelity:** simple equations, merged-cell tables, page-number restart + Roman format, and a
  centred page-number footer all measured faithful in LibreOffice 24.2. **Measured not faithful:** floating
  images. **Untested:** nested tables, first-page/odd-even headers, complex equations, Chinese
  punctuation/kinsoku compression.

### D11 — Warn / downgrade / stop triggers

| Trigger | Behaviour |
|---|---|
| A construction may render differently in one application (floating images, nested tables, columns, first/odd-even headers, page-number restart, complex equations) | **Warn** and continue; report the risk. |
| A preferred construction is unavailable, unsafe, or known-unfaithful and a portable fallback exists | **Downgrade**; always report the downgrade, never silently. |
| The user would need their content changed | **Stop and ask**. |
| The user wants a restructure without having confirmed it item by item | **Stop and ask**. |
| The source cannot be read or fails validation | **Stop and ask**. |
| A requested construction would sacrifice portability and no safe alternative exists | **Stop and ask**. |
| A field cache would be a placeholder, or a page number cannot be guaranteed | **Never ship silently**: either omit/downgrade the item or state it in the change report. |

### D12 — Change report

Every output ships with a short change report containing:

1. **What changed** — the layout operations applied (style set adopted or preserved, page setup, headers/footers,
   automatic content).
2. **Decisions made on the user's behalf** — especially every default applied because nothing was specified.
3. **Warnings** — every construct that may render differently.
4. **Downgrades** — every replacement of a preferred construction with a fallback and the reason.
5. **Unverified / placeholder items** — anything WordFlow could not verify, and any automatic content that is
   intentionally omitted (e.g. TOC page numbers).

### D13 — Render preview

- WordFlow produces a **visual preview** of the output by default, so the user can inspect the result.
- It can be switched off; a disabled preview is noted in the change report.
- The preview is for the user's inspection, not a substitute for the QA checklist (D14), and not a compatibility
  guarantee.

### D14 — QA and Definition of Done

A job is done when **all** of the following hold:

- **Opens without repair** in Word, WPS Writer, and LibreOffice Writer (D10).
- **WordFlow checklist green:**
  - every referenced style is defined (no dangling style);
  - automatic content is populated — TOC entries, captions, cross-references, footnotes — with correct cached
    results and **no placeholders**;
  - every downgrade and warning is recorded in the change report;
  - the source document is verified unchanged;
  - no field is judged "evaluated" on flags alone — a field is judged by its **cached text**.
- **Structural changes** additionally require the user's per-item confirmation before the job is called done.

If any item cannot be met, WordFlow either downgrades-and-reports or stops and asks (D11); it never silently
ships a defect.

## Testing Decisions

- **Test external behaviour, not implementation.** A test asserts what a reader would see and what the change
  report says — page setup, style application, resolved automatic content, warnings, source protection — not
  which OfficeCLI command ran.
- **Fixture-driven, one feature per fixture.** Extend the existing `tests/fixtures/` convention: each promised
  capability has a fixture and a deterministic rebuild script.
- **What the tests must verify:**
  - **Source protection:** the source file's content is identical before and after a job.
  - **Output naming:** default name, collision numbering, and a specified path all work.
  - **Open-without-repair:** each output opens cleanly in Word, WPS Writer, and LibreOffice Writer.
  - **Style integrity:** every referenced style is defined; no dangling style.
  - **Automatic content:** TOC entries, captions, cross-references, footnotes carry correct, non-placeholder
    cached results; TOC page numbers are absent as decided (D9), not wrong.
  - **Rendering fidelity:** fully-supported features render faithfully (LibreOffice measured; Word/WPS
    checked for repair-free open); limited features render as the documented fallback.
  - **Report contract:** warnings, downgrades, and omitted/unverified items appear in the change report.
  - **Refusal paths:** a content-change request, an unconfirmed restructure, and an unreadable source each stop
    and ask instead of producing output.
  - **Reproducibility:** the same source plus the same instructions produce the same layout.
- **Prior art:** the existing 17 single-feature fixtures and `tests/validate-fixtures.sh` are the model; the
  suite already runs schema validation, an issue review, and a screenshot render per fixture.

## Out of Scope

- Editing, authoring, translating, shortening, or correcting content (ADR-0002).
- Restructuring without explicit request and per-item confirmation.
- In-place editing of the source; overwriting the source (ADR-0003).
- Non-DOCX conversion (PDF, Markdown, …).
- A standalone CLI; replacing OfficeCLI or its skills.
- Charts, comments, tracked changes, forms/content controls, watermarks, references & citation styles, mail
  merge, text boxes / WordArt / OLE objects.
- Document-archetype presets (official letter / thesis / report).
- Any dependency on Microsoft Word or Windows.
- Heading levels beyond 4.

## Further Notes

Items below are **not** product requirements; they are open technical points to resolve before or during
implementation. Per project rule, none of them is guessed here.

**Open research (evidence needed):**

- **Multi-page page-number behaviour:** whether a footer `PAGE`/`NUMPAGES` field displays the correct number per
  page without a manual update on a multi-page document (current evidence covers single-page cases only).
- **Nested tables:** render fidelity across the three applications.
- **Different-first-page and odd/even headers:** render fidelity.
- **Complex equations:** OMML render fidelity and the concrete downgrade target.
- **Chinese punctuation / kinsoku compression:** behaviour across Word/WPS/LibreOffice.
- **CJK font availability and substitution:** which of 宋体/黑体 are present or safely substituted on the
  target platforms; whether a fallback chain should be documented.
- **Large-document limits**, and behaviour offline or when fonts are missing.
- **Exact version matrix:** specific Word releases, WPS version, LibreOffice 7.6 vs 24.8+.

**Open implementation decisions:**

- **TOC caching mechanism:** whether a TOC can be cached with entries but no page-number references, or whether
  WordFlow composes the cached entries itself.
- **Correct cached cross-reference text:** the mechanism to write the resolved target text into a content
  reference's cache so it is never a placeholder.
- **Output filename safety:** whether `-排版` is safe in every environment, and whether the default should
  localise.
- **Distribution:** install location and discovery per agent (opencode / Claude / Codex).

**Frozen-decision summary (from this spec):**

- TOC page numbers are omitted in v0.1 (D9).
- Default Chinese fonts are set explicitly — 宋体 body, 黑体 headings, explicit Latin pairing — never the locale
  default (D6).
- The WordFlow standard style set is fixed (D7).
- A template contributes look only — theme fonts, style definitions, page setup — and never content, including
  header/footer text (D1–D3, D5).
- Merged-cell tables are promoted to fully supported; nested tables stay limited (D9).
